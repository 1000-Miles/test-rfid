# Printer sidecar — when the printer is on a different PC than the bridge

The gate bridge must run on the PC wired to the reader and the IR sensor. A
bridge can only print to a queue its **own** operating system can see, so when
the label printer is on another PC it is unreachable — the bridge reports
`queue not found` and no bridge setting can fix it.

The printer sidecar closes that gap: a small service on the printer's PC that
receives finished label bytes over HTTP and hands them to the local spooler.

```
gate bridge PC                    printer PC
reader + IR sensor                label printer
      |
      |  POST /pallet/print  -->  sidecar :3011  -->  spooler  -->  printer
```

This replaces the alternative — sharing the printer over SMB and installing it
as a queue on the bridge machine — which needs two operating systems configured,
Windows credentials stored in a CUPS device URI, and fails in a way
indistinguishable from a dead printer.

## Build the installer

```
cd bridge
npm run build-printer-dist
```

Produces `bridge/dist-printer.zip` (~33 MB). Hand that to whoever sets up the
printer PC.

It bundles `node.exe` and every dependency, so the target PC needs **no Node
install, no npm, and no internet** — which matters, because warehouse PCs are
often locked down or offline.

**The full setup guide is `README.md` inside the zip.** It is generated by
[`bridge/scripts/build-printer-dist.js`](bridge/scripts/build-printer-dist.js),
so it always ships in step with the build rather than drifting from a separate
copy here.

Short version: unzip somewhere permanent, then run `install.ps1` as
administrator. It opens the firewall port, registers a startup task, starts the
service, and prints the PC's IP addresses plus the print queues it can see.

## Point the bridge at it

```
PALLET_SIDECAR_URL=http://<printer-pc-ip>:3011
PALLET_PRINTER_NAME=<exact queue name>
```

or live, over HTTP:

```bash
curl -X POST http://<bridge-ip>:3001/printer/config \
  -H 'Content-Type: application/json' \
  -d '{"palletSidecarUrl":"http://<printer-pc-ip>:3011","palletPrinterName":"TSC T-4403E"}'
```

Confirm `palletSidecarUrl` comes back in the response — a bridge built before
this feature **silently discards** config keys it does not recognise, so it
looks like it worked.

Empty `palletSidecarUrl` means print locally, which is the default and is
unchanged.

## Gotchas that cost the most time

- **Give the printer PC a static or DHCP-reserved IP.** The bridge stores the
  address, so a changed lease stops all pallet printing with no obvious cause.
- **The printer PC must be on.** Inherent to the printer hanging off it, not
  something the sidecar adds.
- **Test from the bridge, not the printer PC.** Reaching the sidecar from its own
  machine proves nothing about the firewall.
